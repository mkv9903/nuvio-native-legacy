# StreamFit — Implementation and Pending Bindings

## Verifiable State

`src/streamfit.c/h` implements calculation, in-RAM history per device/network/host, and an immutable snapshot. `src/streams.c` applies partitioning to the real source list. **Android epoch and real diagnostics are connected**, with disposable N01 window, final HTTP/MIME/host, and cancellation. Epoch/diagnostic status documented in [F03-EPOCH-DIAGNOSTICS-HANDOFF](../../releases/1.8.0/F03-EPOCH-DIAGNOSTICO-HANDOFF.md).

**Exact per-target real runtime (F03, 10/04):** `stream_fit_duracao()` retains up to 8 targets, separating metadata and media; media overrides delayed metadata for the same target, and zero clears only the named provenance. Producers: TMDB movie record (`extras.c`, `runtime` for requested IMDB id); on source sheet opening without pushed value, `app.c` queries catalog (`streamfitdur.c`: "142 min", "1h 52min", `PT1H52M`, numeric minutes) **only** when id matches `alvoPlayer`/`idDoAlvo` — movie via `CatItem.meta`, episode via `CatEp.duracao` for that specific episode, never series/season total; and player (`player_duracao_midia`): backend `video_duracao()` when ready, outside channel/trailer/warning clips, between 2 min and 24 h, never `PLR_DUR_PADRAO`. New file or target resets prior media duration.

**Passive Android telemetry (F03, 10/04):** `PassivoMedidor.kt` aggregates socket bytes read by `ParaleloDataSource` (parallel chunks and single connection) **per wall-clock second** — concurrent connections enter the same bucket, never summing rates measured in disjoint windows. A second counts when ≥90% active transfer and player is actually rendering (playWhenReady in READY/BUFFERING after first READY); active stall counts as zero; memory handoff to ExoPlayer, pause, full buffer (zero active connections), HLS/DASH, and pre-READY startup do not count. Submits 5..48 seconds for the identical final host, network, and session. `streamfitpassiva.c` accepts only native session generations permitted by UI on that frame (real player source) and current epoch; strictly "scheme://authority", no path/query. Sheet displays origin ("Recent playback"/"Diagnostics"), age, sustained Mbps (p20), and "needs ~X of Y Mbps available"; unknown states report reason in a single line. Without obtainable epoch (LG, Samsung TPK/WGT, desktop), the line "no data for this network" is omitted: StreamFit remains unknown and legacy speed test operates strictly as diagnostics. Heavy source moves to end of its own group; heavy auto-selection changes "Best for this TV" to "Automatic choice" without modifying autoplay.

`Stream.tamanhoBytes` originates exclusively from direct property `behaviorHints.videoSize`. The [official Stremio specification](https://github.com/Stremio/stremio-addon-sdk/blob/master/docs/api/responses/stream.md) defines this property as video file bytes. Loose fields, nested `proxyHeaders`, torrent/pack sizes, and "50 GB" strings do not gain this provenance. `tamanhoMB` remains for presentation and legacy ordering; it does not determine weight. The exact reader accepts decimal integers or digit strings without rounding, up to `2^53−1`. Fractions, exponents, negatives, and overflow become unknown. An add-on incorrectly declaring pack size in this field continues requiring provider correction; client does not guess per-episode size.

Engine and source list do not initiate network activity, link resolution, speed tests, transfer threads, or disk I/O. Diagnostic consumer reuses exclusively the explicitly requested test. Zero new dependencies. Builds utilizing `src/*.c`, including Android CMake, discover modules automatically.

## Consumer API

1. **Network/device epoch**: call `streamfit_rede(uint64_t chave)` after detecting a reliable network. `0` indicates unknown. Key is opaque, does not require SSID/IP; belongs to this device/process. Changing key clears all measurements, including returning to a previous network. Never supply a constant key representing different networks. Call `streamfit_limpar()` when invalidating diagnostics/device. Persistence and automatic network change detection are not yet wired.
2. **Real per-host diagnostics**: upon completed media test, invoke `streamfit_diagnostico(epoch, urlFinal, kbpsPorSegundo, n, fimMs)`. Accepts 5 to 48 valid intervals; zero counts, negative / >10 Gb/s rejected. Origin must be **actual measured final host**, not generic speed test endpoint or pre-redirect resolver. Exclude failed tests, HTML/warnings, cache hits, pauses, full buffer waiting, and incomplete/cancelled series. Fresh completed test replaces prior data for that host; stale/repeated submissions rejected. `fimMs` uses civil clock milliseconds, matching `streamfit_agora_ms()`.
3. **Item duration**: call `stream_fit_duracao(alvo, segundos, SF_DUR_METADATA)` with real movie/episode runtime, or `SF_DUR_MEDIA` once backend reports real duration. Target is exact id used in `stream_definir_alvo`, including season/episode. Do not supply `PLR_DUR_PADRAO`, season totals, presumed "45 min", or `player_duracao_seg()` before knowing its provenance. Zero/unknown clears data. Media duration supersedes delayed metadata for same target. File/cut changes require consumer updating/clearing this runtime.
